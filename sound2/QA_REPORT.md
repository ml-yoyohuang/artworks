# /sound2 驗收報告

驗收日期：2026-10-10。結果檔：[`_qa/results.json`](_qa/results.json)；截圖聯絡表：[`_qa/contact-desktop.jpg`](_qa/contact-desktop.jpg)、[`_qa/contact-mobile.jpg`](_qa/contact-mobile.jpg)。

## 環境

- macOS（Darwin 25.5），本機 `python3 -m http.server 8765`（從 repo 根目錄提供靜態檔，與 GitHub Pages 的路徑結構相同）。
- Playwright 1.56.1；**Chromium 141.0.7390.37 headless**，以 `--autoplay-policy=user-gesture-required` 啟動，所以聲音必須真的點擊按鈕才會啟動。
- 視窗：桌機 1440×900（DPR 1）；手機**模擬** 390×844（DPR 2、觸控、mobile UA）。另以 **WebKit（Playwright 內建）模擬 iPhone 13** 做十頁的冒煙測試。
- **沒有在真實手機上測試**；所有手機結果都是模擬視窗。
- 專案沒有 package.json、lint 或既有測試，因此沒有可執行的既有 build／lint 基線；本展不需要建置。

## 實際執行的指令

```bash
python3 -m http.server 8765 --bind 127.0.0.1
PLAYWRIGHT_MODULE=…/node_modules/playwright node sound2/tools/verify.cjs   # 20 組作品 + 2 組目錄 + 韌性測試
```

另外在開發過程中，用暫存腳本逐件截取指定拍點與連續影格（每 0.125–0.5 拍一張），人工檢視動作；那些暫存檔不進版本庫。

## 音畫驗證方法

- **排程對齊**：核心在每個音符排程時記錄 `Transport.getTicksAtTime(音符的音訊時間)`，與樂譜拍點比較。二十組測試的最大偏差都是 0.00000 拍：聲音被放在樂譜指定的拍點上。
- **畫面對齊**：有 `onEvent` 的作品（01–04）記錄畫面事件被派送時，畫面拍子已越過樂譜拍點多少：平均 7–19 ms、最大 34 ms，也就是最多一到兩幀。畫面拍子讀的是 `AudioContext.currentTime − outputLatency` 對應的 Transport 位置。
- **限制**：這些是排程時間與繪圖時間的比較，不是硬體輸出延遲的量測；headless 環境回報的 `outputLatency` 與真實喇叭／藍牙耳機不同。
- **聲音路徑**：以作品自己的分析器（接在主增益之後）量測非零波形，並確認 Tone context 為 `running`、排程器只有一個（`repeats = 1`）。**沒有實際聆聽**：本環境無法播放與聽辨，聲部平衡、音色質感、接縫與爆音沒有經過耳朵檢查。為降低風險：主鏈有壓縮器與 −4 dB 限制器，預設音量 0.65（增益約 0.40），開關聲音以 120 ms 斜坡處理。

## 韌性測試（實測）

| 項目 | 結果 |
|---|---|
| 同一頁連續重新載入並重啟聲音 3 次 | 每次 `repeats = 1`、峰值 0.105–0.129、每秒排程音符數相同（2.5），沒有疊音或多重排程 |
| Tone.js 被封鎖（模擬 CDN／檔案失敗） | 畫面照常（拍子前進），按「開啟聲音」顯示「聲音元件沒有載入；作品以純視覺繼續。」；唯一錯誤是被封鎖的檔案本身 |
| 外部曲目 Carefree | 解碼成功、原樣播放（rate 1）、非零訊號、Transport 暫停、畫面依曲目時鐘前進；目錄 96 BPM／估測 97.0 BPM |
| 外部曲目 Electrodoodle | 解碼成功；目錄 120 BPM／估測 119.7 BPM |
| 切回原創樂譜 | Transport 重新啟動、`repeats = 1` |
| `prefers-reduced-motion: reduce` | 以靜止構圖開始（playing = false），動作幅度係數 0.45 |
| WebKit（iPhone 13 模擬） | 十頁都能啟動聲音（state on）、拍子前進、零 pageerror |

## 關鍵問題與修正（驗收過程中發現）

- 01：原本五條短線排成折線，隱藏介面時被壓成一條細帶，隆起看起來像整條線彎起來。改為預設「五線」長線構圖、加粗線條與光點、隆起靠近起點時淡入、隆起下方加淡色抬升區；折線與環保留為隊形選項。
- 02：形體過小、前景浪太靠近工具列、浪尖泡沫從未出現（用錯了計算來源），全部修正。
- 04：拍點刻痕太小、手機圓盤偏小。
- 06：預覽翻面佔了約 60% 的紙片，重音翻頁波幾乎沒東西可翻；改為約 20%。
- 07：手勢幅度太小、光暈混濁、直向手機時角色與標題和提問按鈕重疊。
- 08：跳躍過高；手機成員太小。
- 09：花形切換的交叉淡化剛好落在綻放那一拍，出現半透明的重影；改到收合的第 3、11 拍。只有內圈退開時花心看不見；改為所有圈層都退開。
- 10：轉身後頭部標記留在錯的一端、整個隊伍偏右半個身長、手機第一位被裁掉。
- 核心：分析器原本接在主增益之前，靜音測試因此失敗；改接在主增益之後再測，通過。
- 目錄：08 的直式裁切切掉了遲到者，改為橫式。
